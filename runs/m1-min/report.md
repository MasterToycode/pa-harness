## 1. 边级：谁修好了

| 口径 | 结果 |
|---|---|
| `gap_too_wide` | **99 / 166 = 59.6%** |
| `no_material_hit` | **25 / 72 = 34.7%** |
| 合计 | **124 / 238 = 52.1%** |
| 705 分母上的良率 | 393 → **517**，55.7% → **73.3%** |

按"哪一手救的"分：

| 算子 | 成功条数 | 说明 |
|---|---:|---|
| `resize_connector` | 58 | 全部是 `gap_too_wide`：只缩半径，锚点不动 |
| `relocate_connector` | 66 | `gap_too_wide` 41 + `no_material_hit` 25：面内改位置 |
| `swap_family` | 0 | 12 次尝试全败（见 §3，这个码下它本来就无效） |

**为什么"缩半径"能救 `gap_too_wide`**（这一条值得单独写下来）：`connector.py:759` 把 `r` 夹到壁厚上限 `t_b/2.25`，接着 `:807-820` 要求 `eng_max > need`，其中 `eng_max = min(d_cap, t_b + gap - 1.25r)`、`need = gap + r`。在 `r == t_b/2.25` 处

```
t_b - 1.25r = t_b - 1.25·t_b/2.25 = 0.4444·t_b = r
⇒ eng_max - need = t_b - 2.25r = 0
```

`eng_max <= need` 恒成立，**于是这条边无论间隙多小都必然判 `gap_too_wide`**。原始 `_theta` 请求的是 `r = r_cap`，被夹到壁厚上限后就落在这个恒等点上。任何严格小于上限的 `r` 都把等式变成富余——这就是 58 条"只改参数就修好"的机制。`asm_000000:6`（gap 仅 0.0048 mm 却失败）就是活样本。

## 4. 未修复归因（下一步该修哪一类）

剩下的 188 条失败边（312 源失败 − 124 修好）分三层：

| 层 | 条数 | 含义 |
|---|---:|---|
| 仍卡在这两个码 | 80 | 还有救，但需要下一手 |
| 目标边退化成更差的码 | 34 | `unreatable_too_small` 18、`degenerate_other` 8、`degenerate_tangent` 3、`peg_detached` 3、`socket_breaks_wall` 2 |
| **不在 M1 授权范围** | 74 | `unreatable_too_small` 29、`socket_breaks_wall` 17、`degenerate_other` 17、`peg_detached` 8、`degenerate_tangent` 3 |

### 4.1 最大的一类：73 条 `gap_too_wide`，全部被"深度上限"卡死

从最后一次尝试的 detail 里把数字读回来（73/73 全部解析成功）：

- `eng_max == edges_v2 的 depth_max`：**73 / 73**（壁厚项 binds 的：0）
- 本地实测 `gap ≥ depth_max`：**57 / 73**，`gap / depth_max` 中位 **1.76**

也就是说：闸门里的 `min(d_cap, t_b + gap - 1.25r)` 永远被 `d_cap` 限住，而 `d_cap = depth_max = 0.8·min(t_a,t_b)` 是**边级文件常量**，与锚点处的实际间隙无关。当界面实际间隙比这个常量还宽时，**任何半径、任何面内位置都不可能过闸**。

`eng` 的语义是"露出 A 外表面的功能啮合长度"（`connector.py:590-593`），本质是**伸出长度**，却被 `min(t_a,t_b)` 这种"厚度"量卡住。这是语义层面的问题，不是调参能解决的——**这是下一步最该修的一类**。三条候选路线（都要请示，因为改算法）：

1. 让 `d_cap` 从锚点处实测的局部 `t_a/t_b` 现算，而不是读文件常量（`feasibility` 已经支持 `t_a/t_b` 入参，只是 `depth_max` 优先）；
2. 把 `eng` 的约束改成只由 B 侧壁厚给（`t_b + gap - 1.25r`），去掉 `min(d_cap, ...)`；
3. 承认这类"界面本来就没贴合（`interface_type=near`/实测 gap 大）"的边是数据属性，交给 `add_connector`（跨缝加长销，属于 §5.3 表的下一格，M1 未授权）。

### 4.2 第二类：18 条退化到 `unreatable_too_small`

局部 `t_b` 实测 0.045–0.54 mm，`r_wall_max = t_b/2.25` 落到 0.02–0.24 mm，**低于 0.25 mm 打印下限**。这是真正的薄壁数据限制，不是策略问题。按 §9.1 的判据，这类"上不去说明瓶颈是墙厚/特征尺度"的情况**该换的是数据不是方法**。

### 4.3 第三类：11 条退化到 `degenerate_other` / `degenerate_tangent`

锚点落在近乎相切（`|cos| < 0.087`）或补丁边缘的面片上。25 点网格里有位置能测到材质，但表面朝向太斜，销轴几乎贴着壁走。这类需要"换面"而不是"换点"，M1 没有这个算子。

### 4.4 第四类：7 条 `no_material_hit` 无解 + 5 条过往闸后死在体积检查

7 条在 25 个网格位置全部打不到材质（其中 7 条连一次 build 都没花，`stopped=no_plan`）；5 条过了闸但 `peg_detached`/`socket_breaks_wall`——那是"位置找到了、销做不出来"，需要 §5.3 的 `add_connector` 或换家族重建模，M1 未授权。

## 5. 两条不许当结论的断言（已核）

### 5.1 修好后仍然可打印：124 / 124

判据：`r ≥ 0.25 mm` 且 `wall_remaining ≥ 0.25·r`（后者 `connector.build` 在 `clamp=True` 时**不检查**，`connector.py:855`，所以必须自己验）。

- `r` : min 0.254 / p25 0.404 / **p50 0.612** / p95 2.618 / max 5.528 mm；**落在 0.25 mm 下限的：0 条**。
- `wall_remaining / (0.25 r)`：min 0.999997（6 位小数的存储舍入，不是违规）、p50 3.14 —— 有 **37 条正好压在**壁厚下限上（`wall = 0.25 r`），是半径夹取的自然结果，合法但没有余量。
- 所以"修好了"= 能建出闭合（`bnd1==0`，`connector.py:906-910` 强制）+ 满足绝对打印下限；**不等于"和原来一样结实"**。销更细（p50 半径 0.61 mm）或位置换了，强度只能用载荷/稳定性指标另说，M1 没有测。

### 5.2 有没有动非目标部件：没有（71 个装配逐件 hash 前后一致）

- `connector.build` 返回 `a_out`/`b_out` 是**新网格**；输入的两个 `Trimesh` 必须原样返回。把装配里**每个**部件在修复前/后各 sha1 一次（`parts-hash.jsonl`），**71 个装配、0 个部件变了**。
- 全程没有写 `rl_assembly/` 任何文件，输出只进 `runs/m1-min/`。

### 5.3 一个要主动交代的副作用：66 条修复靠"挪锚点"

- `relocate_connector` 成功 66 条（另 58 条 `resize_connector` 位移为 0），位移 p50 **0.79 mm**、p95 **14.1 mm**、max 22.3 mm。
- 搜索范围限在 `±0.72·half_w / ±0.72·half_h` 内（源自己的 `±0.9h` 裁剪框再留余量），所以位移都落在记录下来的接触补丁 bbox 内；但**这不是"同一个销换个尺寸"，是"换个位置打销"**。审计时按 `final.params.shift_mm` 分档看。
- 换位后的合法性证据是量出来的：新位置两侧都有材质、且实测 gap 满足闸门。

### 5.4 销要跨过的实际间隙（不是零）

修复成功的 124 条里，销从 A 的表面跨到 B 的表面，中间那段间隙 p50 约 0.65 mm：

| 算子 | n | gap min | p50 | max | gap ≤0.2 mm |
|---|---:|---:|---:|---:|---:|
| `resize_connector`（锚点未动） | 58 | 0.000 | 0.644 | 3.670 | 14 |
| `relocate_connector`（挪了锚点） | 66 | 0.010 | 0.707 | **9.470** | 11 |
| 合计 | 124 | — | — | 9.470 | **21 / 124** |

所以"修好"的严格含义是：**在这个位置上能造出一根满足打印下限的销把两个件连起来**，销的长度 = `gap + r`（中位 1.40 mm，最长 15.0 mm）。只有 21 条落在"界面几乎贴合（gap ≤0.2 mm）"的情形。对 225 mm 尺度的件来说 0.6 mm 是 0.3%，可以接受；但 9.5 mm 那条（`asm_000002:25`）是一根 11 mm 长销，属于"跨缝连接"而不是"贴面连接"，读良率时要知道它算在里面。

## 6. 一个必须写下来的错误：第一遍全废

第一遍（`_pass1-buggy-basis/`）的结果是 **62/238**，其中 `no_material_hit` **0/72**。原因不是方法无效，是**我抄错了面内基**：

- `connector.plane_basis`（`:138-145`）是 `ref = (0,0,1) if |n_z|<0.9 else (1,0,0); e1 = ref×n; e2 = n×e1`；
- 我按"Gram–Schmidt 随便挑一个正交方向"自己写了一个，二者相差一个旋转；
- 后果：`relocate_connector` 用我的基把 `(u,v)` 换算成世界点，源用它的基换算 —— **量到材质的位置和打销的位置不是同一个点**，于是"测量说有材质、build 说没材质"。闸门自校准立刻暴露了它：假阳性 **103**/379。
- 修好后：`no_material_hit` 25/72，闸门自校准 **369/379 一致（假阳 10、假阴 0，2.6% 误差）**。

教训写进测试了：`test_plane_basis_matches_the_source_construction` 把源的构造逐分量钉死。**"显然可以直接抄的纯函数"是最贵的一类错误**——它不报错，只是把几何悄悄挪走。

## 7. 与记忆卡 56.7%→68.2% 的关系

记忆卡记的是"只修锚点重跑 228 条成功 97（救回 42.5%），可行边成功率 56.7%→68.2%"。本次 238 条救回 52.1%，55.7%→73.3%，**量级一致且更高**。差异有解释：

- 本次多了 `resize_connector` 这一手（58 条纯半径修复，锚点没动），记忆卡那轮是"只修锚点"；
- 只算锚点修复的话，本次是 66/238 = 27.7% —— **低于** 42.5%。差别很可能在锚点重选的方式：记忆卡那轮是重跑锚点选择（gap-first 策略换点），本次是面内 25 点网格 + 闭式解筛选。**如果下一步要在锚点这条线上追平 42.5%，该做的是把 gap-first 的锚点策略接进来，而不是加大网格。**（按任务书 §第二步，重选锚点需复用 `refine_edges.py`，而它会整装配重跑 `cg.build`（19 s/装配），本轮没走这条路，仅用面内位移近似。）

## 8. 结论：M1 的天花板在哪

- **能修的**：`gap_too_wide` 里被壁厚等式卡住的那一半（59.6%）、`no_material_hit` 里锚点落在补丁边上的那三分之一（34.7%）。
- **修不动的**：73 条深度上限卡死（语义问题，需改算法）+ 18 条真实薄壁 + 11 条相切面 + 7 条无材质 + 5 条过闸后体积失败。
- **所以 M1 的天花板不是 100%**：在"不改几何、不改算法、每边 ≤3 次"的约束下，52% 已经是这一手上限附近（闸门自校准 2.6% 误差说明模型没在自我欺骗）。
- 装配级只 +6 是**数据与评估协议的性质**，不是方法的失败：28 个仍未可解的装配里 20 个还带着 47 条 M1 无权修的失败边。
